# 사이트 설계도(PRD) — 코웨이 렌탈 맞춤 상담 (가칭, 이름 미정)

작성일: 2026-10-10 · 이 문서는 사이트를 고칠 때마다 다시 보는 기준이다.

참고 사이트(읽기만 하고 수정하지 않는다):
- 제품 정보 블로그: https://coway.blogpro.so/
- 상담·접수 사이트: https://coway-consult.vercel.app/

## 1. 한 줄 정의
코웨이 정수기·공기청정기·비데·매트리스를 손님이 직접 비교하고, 몇 가지 질문으로 맞는 제품을 추천받은 뒤 무료 상담을 신청하는 코웨이 전문 상담 사이트.

### 사이트 목적
- 손님이 용도와 조건에 맞는 코웨이 제품을 쉽게 찾는다.
- 제품별 정보, 월 렌탈료, 프로모션, 제휴카드 혜택을 한곳에서 본다.
- 상담 신청을 한곳에 모아 놓치지 않고 처리한다.
- 폰에서 편하게 쓴다(폰 화면 우선).

## 2. 손님
- 누가: 가정 고객(1~4인 가구) · 사업장 고객(카페·식당·학원 등 소형·중형 매장) · 법인·공공기관 담당자 — 세 부류 모두
- 어디서 알고 오나: 검색·기존 블로그 글 · 지인 소개·명함·QR·카톡 링크 · SNS·광고 — 모두

## 3. 손님이 궁금한 것 (연락하기 전에)
1. 월 렌탈료가 얼마인가
2. 설치와 관리는 어떻게 되나 (설치 가능 여부, 설치일, 정기 관리 방식)
3. 지금 받을 수 있는 혜택은 무엇인가 (이달의 프로모션, 제휴카드 할인)

## 4. 믿게 할 증거 (실제로 있는 것만)
- 소속·직함: 코웨이 본사 세일즈 팀장 (이름·사진: 미정)
- 직접 쓴 제품 글·사진: 기존 블로그의 실사 리뷰와 제품 안내 글로 연결
- 후기: (실제 후기가 생기면 넣는다. 지금은 자리만)
- 법인 견적·납품 사례: (실제 사례가 생기면 넣는다. 지금은 자리만)

## 5. 누르게 할 버튼 하나
- 버튼 이름: 무료 상담 신청
- 누르면: 문의 폼
- 보조 버튼: "30초 맞춤 추천" (추천 결과 화면에서도 같은 무료 상담 신청 버튼으로 이어진다)

## 6. 페이지 구성 (위에서 아래로)

### 메뉴
홈 · 제품·렌탈료 · 맞춤 추천 · 혜택 · 무료 상담 신청(버튼)

### 페이지 구조 (3장 + 관리자)
| 주소 | 내용 |
|---|---|
| `/` 홈 | 아래 "첫 화면 구성" 순서대로 한 장 |
| `/products` 제품·렌탈료 | 정수기 · 공기청정기 · 비데 · 매트리스 탭. 제품마다 사진, 특징 2~3줄, 월 렌탈료, 블로그 상세 글 링크, 상담 신청 버튼 |
| `/recommend` 맞춤 추천 | 제품군 선택 → 질문 3~4개 → 추천 제품 1~2개 → 무료 상담 신청 |
| `/privacy` 개인정보 처리방침 | 자리만 만든다. 내용은 운영자가 채운다 |
| `/admin` 관리자 | 비밀번호로 잠김. 검색에 노출하지 않는다 |

### 2026-10-11 바뀐 점 (운영자 요청)
- 메인에는 **주력 제품·신제품만** 보여 준다(목록은 `assets/common.js`의 FEATURED). 전체 제품은 `/products`에서 본다.
- **상담 바구니**: 제품을 담아 두고 `/consult`(상담 바구니 페이지)에서 담은 제품을 확인한 뒤 한 번에 상담을 신청한다. 문의 폼은 홈이 아니라 이 페이지에 있다.
- 제품·금액은 `data/catalog-prices.json`을 읽어 자동으로 보여 준다. 금액이 바뀌면 이 파일만 바꾼다.
- 구조는 운영자가 준 레퍼런스(공지 띠 → 메뉴 → 첫 화면 + 제품 패널 → 카드 묶음 → 어두운 혜택 띠 → 상담 띠 → 바닥글)를 따랐다.

### 첫 화면 구성 (홈) — 처음 설계
1. 첫 화면 — 한 문장 + [무료 상담 신청] 버튼 + [30초 맞춤 추천] 보조 버튼
2. 누구에게 맞나 — 가정용 · 사업장용 · 법인용 세 갈래
3. 제품군 네 가지 — 정수기 · 공기청정기 · 비데 · 매트리스 (누르면 `/products` 해당 탭)
4. 궁금한 것 세 가지 — 월 렌탈료 · 설치·관리 · 이달의 혜택(프로모션·제휴카드)
5. 상담하는 사람 — 소속·직함, 블로그 글 바로가기
6. 후기 자리 (비워 둠)
7. 문의 폼 (무료 상담 신청)

### 맞춤형 제품 추천 기능
- 범위: 정수기 · 공기청정기 · 비데 · 매트리스 네 가지 모두
- 흐름: 제품군 고르기 → 질문 3~4개(한 화면에 하나씩, 보기 누르기) → 추천 1~2개와 추천 이유 → [이 제품으로 무료 상담 신청]
- 추천 결과에서 상담을 신청하면 고른 답과 추천 제품이 문의 내용에 자동으로 붙는다.
- 추천은 미리 정한 표(조건 → 제품)로 한다. AI가 그때그때 지어내지 않는다.
- 질문 초안 (운영자가 확인 후 확정):
  - 정수기: 어디에 두나요(가정/사업장/법인) · 몇 명이 쓰나요 · 필요한 기능(냉·온·정·얼음) · 놓는 방식
  - 공기청정기: 공간 크기 · 가습 필요 여부 · 가장 큰 고민
  - 비데: 원하는 기능 · 관리 방식
  - 매트리스: 사이즈 · 원하는 단단함 · 스마트 기능 필요 여부
- 조건별 추천 제품 표: 초안은 [blog-info.md](blog-info.md) 7번에 있다(블로그 글의 특징만으로 만든 것). 추천 결과의 금액은 [products.md](products.md)(카탈로그)에서 가져온다. 운영자가 확인한 뒤 확정한다. 제품 사양·수치는 지어내지 않는다

### 상담 및 렌탈 접수 절차
1. 손님이 문의 폼 작성 → 저장 → "상담 신청이 접수됐어요. 확인 후 연락드릴게요." (지킬 수 없는 답변 시간은 쓰지 않는다)
2. 운영자가 `/admin`에서 새 문의 확인 → 전화·카톡으로 상담
3. 렌탈 접수(계약·설치 주소·결제)는 **사이트 밖에서** 상담 중에 직접 진행한다.
4. 처리 상태: 새 문의 → 연락함 → 완료

## 7. 문의 폼에서 받을 것
- 이름, 연락처
- 구분: 가정 / 사업장 / 법인
- 관심 제품: 정수기 / 공기청정기 / 비데 / 매트리스 (추천 결과에서 오면 자동 입력)
- 문의 내용 (선택)
- 개인정보 수집·이용 동의 (필수) — 목적·보관 기간 한 줄 + 처리방침 링크
- **받지 않는 것: 카드번호 · 계좌번호 · 주민등록번호 · 상세 주소**

### 고객 정보 저장 및 관리자 기능
- 저장: Supabase `inquiries` 표 (leaderpl-admin 스킬 기준)
- 관리자 페이지 `/admin`: 새 문의 개수, 최신순 목록, 상태 바꾸기(새 문의 → 연락함 → 완료), 연락처 눌러 복사, 폰 화면 우선
- 접근 권한: **운영자 한 명만.** 관리자 비밀번호 하나로 접속한다.

### 개인정보 보호
- 꼭 필요한 것만 받는다(위 폼 항목). 동의하지 않으면 저장하지 않는다.
- 브라우저 쪽 코드에는 데이터베이스 키를 두지 않는다. 저장·조회·수정은 서버(`/api`)만 한다.
- 표는 행 보안(RLS)을 켜고 정책을 만들지 않는다 → 공개 키로는 아무도 읽고 쓸 수 없다.
- 키와 비밀번호는 코드·파일·커밋에 적지 않고 환경변수로만 읽는다.
- `/admin`과 `/privacy` 외 회원 화면은 없다. `/admin`은 검색 노출 금지(noindex).
- 관리자 비밀번호는 화면 공유·단톡·채팅에 쓰지 않는다.
- 보관 기간: (미정 — 운영자가 정한다. 예: 상담 완료 후 일정 기간 뒤 삭제)
- 손님이 삭제를 요청하면 운영자가 Supabase 화면에서 직접 지운다. 절차는 처리방침에 적는다.
- 개인정보 처리방침 내용: (미정 — 운영자가 작성. 지어내지 않는다)

## 12. 만드는 방법 (클로드가 끝까지 만들 때 기준)
- 분위기: 따뜻한 (부드러운 색, 둥근 모서리, 집·가족·친근한 상담사 느낌) · 참고 디자인: 기존 두 사이트의 내용과 기능만 참고 — 그대로 베끼지 않는다. 색·글꼴은 클로드가 정함
- 문의 저장: 예 → Supabase(leaderpl-admin 스킬) + /admin
- 회원가입: 이번엔 아니요
- 배포: GitHub 공개 저장소 + Vercel
- 표기: 코웨이 본사 공식 사이트가 아니라 세일즈 팀장 개인이 운영하는 상담 사이트임을 아래쪽에 밝힌다. 코웨이 로고·제품 사진을 써도 되는지는 운영자가 확인한다. (미정)

## 13. 만드는 순서 (클로드가 처음부터 끝까지 한 번에)

### 개발 우선순위
1. 스타일(색·글꼴)을 분위기에 맞게 정하고 홈 첫 화면부터 만든다
2. 문의 폼 → Supabase 저장 → `/admin` 관리자 페이지 (문의가 들어오는 길을 먼저 연다)
3. `/products` 제품·렌탈료 (금액표를 받은 제품부터)
4. `/recommend` 맞춤 추천 — 정수기 먼저, 그다음 공기청정기 · 비데 · 매트리스 순서로 하나씩
5. 혜택(프로모션·제휴카드) 영역과 `/privacy`
6. GitHub 공개 저장소에 올리고 Vercel로 배포해 내 주소를 만든다
7. 다 만든 뒤 한 번에 보고: 내 사이트 주소 · 관리자 주소 · 확인 방법 · 사용자가 할 일
- 사용자가 직접 할 일(이때만 멈춤): 로그인, 결제, 관리자 비밀번호(ADMIN_PASSWORD) 입력

### 만들기 전에 운영자가 줄 것
- [products.md](products.md) 맨 아래 "확인 필요"에 적힌 제품의 금액
- 사이트에 올릴 제품 고르기 (카탈로그에는 네 제품군 70개 제품이 있다. 전부 올릴지, 주력 제품만 올릴지)
- [blog-info.md](blog-info.md) 7번 추천 표 초안 확인
- 블로그의 연락 방법을 그대로 쓸지, 상담 가능 시간·지역, 표기할 이름
- 개인정보 보관 기간과 처리방침 내용
